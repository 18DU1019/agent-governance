## 件 1：SUSPENDED 语义（"无法检查"独立输出态）

- **借件原文**：CAP 一致性检查把"检查未能执行"与"检查通过/失败"并列为第三态，防止工具故障冒充绿色结论。
- **我方对应坑**：sync_check 旧版把不可读文件写成占位符照常入哈希，两侧同样不可读时占位符相同即报"字节一致"——权限故障被伪装成一致性结论。
- **机械承载**：已实施（commit bf00271）：`tree_hash` 返回不可读计数，遮蔽判定任一侧计数 >0 时输出 `SUSPENDED 无法检查`，占位符不参与一致判定。
- **条款面提案**：`junction-discipline.md` 第三节"遮蔽检测"句补判定档位说明——内容判定为四档：字节一致 / 内容一致仅行尾差异 / 内容分叉 / SUSPENDED（无法检查）。
- **硬化注（自带字段定义，勿借半成品）**：SUSPENDED 态必须携带最小字段集 `{不可读文件数, 侧别(副本/正本), 复检动作}`，缺一律按"检查未执行"处理不得输出态文本。SOOS 自家 GAR 草案留有同型缺口（SDB-GAR-05：SUSPENDED 无强制字段集），本条即对该缺口的补全。
- **反题**：SUSPENDED 态使"绿"的含义变窄（绿=检查执行且通过），报表读者可能把 SUSPENDED 当 WARN 忽略。合题：SUSPENDED 计入异常条数、退出码维持 FAIL(1)，不允许静默。

## 件 2：四相修订传播 + `supersedes` 血缘字段

- **借件原文**：CAP 把一次修订的传播拆为四相（提案→批准→生效→旧版废止），且新版本文档携带 `supersedes` 字段显式指向被废止版本。
- **我方对应坑**：R4 模板血缘断点——仓内模板与生产正本版本无对照记录（CHANGELOG Unreleased 已记最小件：模板头部 lineage 注）。
- **提案**：作为**流程参考**收编，不立强制条款。`templates/` 两模板头部 lineage 注（已落 cd27cbb）补一个字段位：`supersedes: <旧版本号或 commit>`，无旧版时填 `null`。四相模型本身不引入——本仓单维护人形态下"提案/批准"两相塌缩为一次裁定，引入四相即过度工程。
- **反题**：只借字段不借流程，可能丢失四相的价值（防止"生效"与"废止"脱节——旧版未废止造成双活）。合题：双活风险本仓已由公理 5（正本唯一）+ 校验器遮蔽检测机械覆盖，四相中"生效≠废止"的洞已有别的闸补，无需叠层。

## 件 3：双重评估（人批准后、执行前再查一次）

- **借件原文**：CAP 要求动作经"自动评估→人工批准→执行前复评"两道独立评估，防批准时点与执行时点之间状态漂移。
- **我方对应坑**：读数会说谎第一问（此刻仍真？）的自动化形态——批准依据的读数在执行时可能已过期。本仓已有同型实践：push 前 SOP 五步全量重扫（不信任提案时点的扫描结果）。
- **提案**：`lifecycle-clauses.md` 新增候选条款（暂编号 9，采纳后定稿）："**不可逆动作的执行前复扫**——门禁批准与执行之间存在其他写操作可能的（并发会话、时间间隔跨天），执行时点必须重跑关键校验，禁止引用批准时点的旧读数作为放行依据。"
- **边界**：批准与执行同轮连续完成的不强制复扫（防仪式化空转，与 closure-workflow 反题条款一致）。
- **反题**：单人体系里"批准即执行"是常态，此条多数时候是空转税。合题：触发条件写死为"跨轮次或跨写者"，同轮不触发——税只在漂移风险真实存在时收。

## 件 4：PT 渐进信任降权（信任分随违规衰减、可恢复）

- **借件原文**：CAP 的 Progressive Trust 给执行主体记信任分，违规自动降权、观察期后恢复。
- **我方对应坑**：生产体系有"渐进四阶段"授权形态但无量化件；本仓无对应物（如实披露：本件的落点在生产体系，不在开源仓）。
- **提案**：**本仓不立条款**，登记为生产侧观察项。理由：本仓治理对象是静态资产（skill 文件），无"执行主体"可记分；把 PT 搬进本仓是为借而借。
- **反题**：Agent 端作为挂载/改链主体确有行为史（误删正本事故形态），可记"端"级信任分。合题：端级信任的机械承载已是校验器 FAIL 退出码 + 纪律 2 的人工操作规范，量化记分在单人双端形态下无决策增益（分数不改变任何动作阈值），待多端形态出现再议。

## 件 5：DAM 三层写权限命名（read / propose / commit 分档）

- **借件原文**：CAP 的 Discretionary Authority Model 把主体对对象的权限显式命名三档：只读、可提案、可提交。
- **我方对应坑**：公理 5（正本唯一）与公理 3（不可逆必门禁）已有"谁能改正本"的实质约束，但无命名——"传引用不传副本"的权限语义靠读者自行意会。
- **提案**：`paradigm.md` 共享公理节后补一行口径注（不改公理正文）："正本写入权限三档命名可借用：read（消费方）/ propose（可提改动案，如 issue/PR）/ commit（可直改正本，本仓=维护人）。"
- **修正记录**：借件清单 v4 原句标"公理 3（正本写入）"系编号错位——公理 3 为不可逆必门禁，正本写入归属公理 5。本稿按修正后口径落位。
- **反题**：三档命名对本仓是纯修辞（实际只有 commit 一档有人持有）。合题：修辞价值在于给外部贡献者声明 propose 通道（issue forms 已存在，命名使其显性），成本一行，采纳。

## 件 6：OQ 命名登记法（Open Question 编号 + 状态 + 触发条件三要素）

- **借件原文**：CAP 把未决问题编号登记，每条强制带状态与重审触发条件。
- **我方对应坑**：`paradigm.md` 摄入层已有"挂账+重审触发器；无触发器的挂账不过夜"——与本件同构，且我方口径更严（无触发器直接不许挂账，CAP 允许登记后补）。
- **提案**：**不借**，反向对照登记：CAP 此件为我方既有纪律的弱版本，收编只会稀释。在裁定记录中保留此对照结论即可。
- **反题**：CAP 的"编号"面我方缺失——我方挂账散在会话记忆与看板行号，无全局编号，跨会话引用靠日期+描述定位。合题：编号面可借、三要素面拒（我方已更严）。落点为运行台看板纪律，非本仓条款，登记为观察项。

## 件 7：负面一致性向量（Negative Vectors：显式定义"什么算不合规"）

- **借件原文**：CAP 除正向合规要求外，显式枚举不合规形态向量，检查器对负例向量逐条验证。
- **我方对应坑**：sync_check 只验正例拓扑，CI 负例目前仅悬空链接一类（ci.yml 负测试）。已知负例形态清单散在审查史：遮蔽副本、链接名不一致、指向旁支、静默失败、占位符冒充一致（本轮新堵）。
- **提案**：`junction-discipline.md` 第三节末补一小节"负例向量清单"，把校验器已覆盖的异常形态显式枚举（每条：形态描述 → 校验器判定点），作为覆盖面口径的显性化——与 CHANGELOG v0.1.3 勘误教训（完整性声明须带覆盖面口径）同一条纪律的自检应用。
- **反题**：清单与代码双写必然漂移（文档清单漏更新）。合题：清单条目直接引用代码行为（CI 负测试用例号），漂移由负测试红绿兜底；无机械用例支撑的条目不得入清单。

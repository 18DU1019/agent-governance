# 治理范式图谱（Governance Paradigm Map）

本仓库五件资产共享同一组公理。本文把它们显性化，作为阅读入口与裁剪指南。

## 五层范式（Five Layers）

| 层 | 范式 | 内核 | 仓库落点 |
|---|---|---|---|
| 输入 | 知识摄入 | 二手→一手验证→对照我方→净裁定（采纳/不采纳/挂账+重审触发器）；无触发器的挂账不过夜 | templates/kb-ingest-gate |
| 对象 | 矛盾裁决 | 正本唯一+传引用不传副本；机械裁决格式、认知裁决语义，两层分离 | tools/sync_check.py（机械层实例） |
| 工程 | 发布准备 | 范围裁定→正本零触碰 copy-out→清单化脱敏三段（隐私/耦合/叙事）→真盲写→参数化回归→不可逆动作门禁 | 本仓 git 史即教材 |
| 内容 | 生命周期治理 | 登记三防、降档时钟带触发器、记账修复先于扩张、收尾四步+反仪式化指标 | governance/lifecycle-clauses、closure-workflow |
| 协作 | 跨会话安全 | 禁碰协议/双笔提交/append-only 审计/精确 add/主会话 trust-but-verify 独立复扫 | governance/junction-discipline 纪律 1-4 |

## 共享公理（Axioms）

1. **证据分级**：一手 > 二手 > 模拟；且证据强度不对称——清单上读出"在列"有效，读出"不在列"无效（可能被截断）。可见性争议一律运行时探测定谳。
2. **裁决分层**：机械层管格式一致性（可自动判定、零成本复跑），认知层管语义综合（模型/人）。两层不许互相越位：机械层不裁决语义，认知层不重做机械比对。
3. **不可逆必门禁**：建仓、push、删除、批量降级等动作单独取裁，不随"继续/接手"类指令自动放行。
4. **账本只追加**：审计与变更记录不回填修改；失真用显式修复流水治理，不用洗数。
5. **正本唯一**：副本必须可追溯回正本（引用/链接/哈希）；双写者形态出现即挂触发器重审。

## 适用边界（Scope Rule）

全套五层仅在**长寿命资产 + 跨会话/跨端一致性需求 + 不可逆风险**三者齐备时启用。一次性任务只保留最小两件：传引用（公理 5）+ 门禁（公理 3）。

反题照例呈现：重治理对"单人+少量 Agent"可能过度工程——业界实测多 Agent token 倍增（orchestrator-worker 约 15×）提示"模型能自己协调就别加脚手架"。本范式的回答是划界而非取平均：脚手架的正当性来自资产寿命与不可逆性，不来自任务复杂度本身。

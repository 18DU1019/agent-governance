# 跨端 Skill 正本治理纪律（Junction Discipline）

适用场景：同一套 skill 目录被多个 AI Agent 端（如 TRAE / WorkBuddy / Claude Code 等）共同加载时，如何保证"一份正本、多端挂载、可校验、不产生分叉"。

## 一、挂载模型

- 正本目录（source of truth）存放实体文件；各 Agent 端的 skills 目录内对应项为**链接**（Windows NTFS junction / Unix symlink），指向正本同名子目录。
- 禁止"每端各存一份副本"——副本必然漂移，且漂移以"内容看似相同、字节不同"的隐性形态积累。

## 二、四条纪律（违反即事故）

1. **正本目录内禁止再建任何链接**——防止链接环与递归扫描事故。
2. **卸载链接只用 `rmdir <链接名>`（不带 `/S`）**——对链接路径使用递归删除会穿透删掉正本。全程禁用 `rd /S` 作用于链接。
3. **链接所在的各端目录永不入 git**——git 不理解链接语义，会把指向内容当实体重复跟踪；版本仓库只建在正本目录。
4. **备份命令必须排除再解析点**——Windows `robocopy` 需加 `/XJ`，防止跟随链接造成数据重复或放大。

### 机械承载标注（2026-10-03 补，克制类条款与校验器对应关系显性化）

| 纪律 | 承载层 | 依据 |
|---|---|---|
| 1 正本内禁建链接 | 校验器机械 | sync_check 以 os.walk 递归扫描正本目录树（含子目录）全部 reparse point，命中即 FAIL（v0.1.5.1 起覆盖任意深度，此前仅顶层） |
| 2 rmdir 不带 /S | 文档级（人工） | 属操作动作纪律，静态校验器无法拦截运行时误操作 |
| 3 各端目录不入 git | 文档级（人工） | 属仓库配置纪律，校验器不介入各端 .gitignore |
| 4 robocopy /XJ | 文档级（人工） | 属备份命令纪律，校验器无备份钩子 |

判定口径：四条纪律中仅第 1 条由校验器机械承载，第 2-4 条为文档级（依赖人工遵循）。此标注如实呈现覆盖面边界——校验器绿≠四条纪律全守。

## 三、一致性校验器设计要点（sync_check.py 的设计依据）

- **自动发现挂载，不维护硬编码名单**——名单制无法发现"漏挂/多挂"，且每次挂载变动都要改脚本。
- **遮蔽检测**：某端出现与正本同名的**实体**目录即为事故形态（说明该端实际加载的是副本而非正本），必须报错并给出内容判定。内容判定为**四档**：字节一致 / 内容一致仅行尾差异 / 内容分叉 / **SUSPENDED 无法检查**（任一侧存在不可读文件时，占位符不参与一致判定，须修复读取权限后复检——"无法检查"是独立输出态，不得冒充前三档中的任何一致结论）。
- **链接侧读取完整性判定（v0.1.5.1）**：SUSPENDED 语义同样覆盖链接分支——透过链接读到不可读文件即报 SUSPENDED，链接侧无可校验文件（空项/全忽略项）即报 FAIL。链接侧不做内容哈希比对（链接读的就是正本，同义反复无检测力），只做读取完整性判定。
- **参数前提校验（v0.1.5.1）**：`--source` / `--mount-a` / `--mount-b` resolve 后两两不同，配错退出码 2——同路径双端会拿到假绿，挂载端=正本会产生误导性"遮蔽"报告。
- **链接名一致性判定的跨平台语义注**：名比对为大小写敏感。Windows（NTFS 大小写不敏感）下 `SKILLA`→`skillA` 链接指向同一对象仍判"名不一致"，属**保守误报**；Linux 下同名拓扑为真不一致，判定正确。两端判定结果一致（均 FAIL），差异仅在语义解释；如需平台感知比较，走 issue 提案。
- **身份配对按目录名**（v0.1 实现口径）——目录名与 SKILL.md 内部 `name` 字段不一致属上游卫生问题，由 frontmatter lint 把关，不在挂载校验器职责内；校验器只做拓扑与内容一致性。
- **跨端比对先归一化行尾再哈希**——不同工具链产出的 CRLF/LF 差异会制造大量"字节不同、内容相同"的伪分叉；凡跨端比对，先 norm() 后 hash，并区分报告"字节一致"与"内容一致"两档。
- **对链接做可达性判定要用心**：Windows 目录联接在部分 API（如 `os.path.islink`）下返回 False，须用 reparse point 属性判定。

### 负例向量清单（v0.1.5 补，覆盖面显性化）

校验器只验正例拓扑不足以证明覆盖面——把"什么算不合规"逐条显式枚举，读者才能看出哪些形态**没有**闸。每条须能指回代码判定点；无判定点支撑的形态不得入本清单（入则即失真）。

| 不合规形态 | 校验器判定点 | 回归用例覆盖 |
|---|---|---|
| 正本目录树内（含子目录）建链接（循环扫描风险） | os.walk 递归扫描 reparse point（v0.1.5.1） | **有**（selftest case6） |
| 链接指向正本树外（旁支目录） | realpath 后严格父子判定 | **有**（selftest case11） |
| 链接指向的正本项已消失 | 目标名不在 masters 集 | **有**（selftest case12，以 hub 内非顶层目录构造等效触发同一判定路径） |
| 链接名与正本目录名不一致 | 名比对 | **有**（selftest case13） |
| 透过链接存在不可读文件（静默漏判） | 链接侧 tree_hash 不可读计数 >0 → SUSPENDED（v0.1.5.1，旧判据"链接 n=0 而正本 n>0"对合法链接恒 False，属死代码） | **有**（selftest case5） |
| 透过链接无可校验文件（空正本项/全忽略项） | 链接侧 tree_hash 文件数=0 → FAIL | **有**（selftest case9） |
| 同一端重复挂载同一正本（多挂） | 端内目标名重复检出 → FAIL | **有**（selftest case10） |
| 参数配错（双端同路径 / 挂载端=正本） | resolve 后两两比较，命中退出码 2 | **有**（selftest case7/case8） |
| 悬空链接（目标不存在） | `is_link` 且非目录 | **有**（ci.yml 负测试 + selftest case4） |
| 实体副本遮蔽正本同名项 | 挂载端实体目录命中 masters 名 | **有**（selftest case2） |
| 副本/正本含不可读文件 | tree_hash 不可读计数 >0 → SUSPENDED | **有**（selftest case2b/2c） |
| 挂载端目录不存在 | exists 判定 | **有**（selftest case14） |
| 正本树内文件级链接（树外内容透过链接计入正本哈希） | os.walk filenames 级 is_link 判定（v0.1.5.2，纪律1"任何链接"含文件级） | **有**（selftest case16；Windows 无文件级 symlink 权限时自动跳过，CI Linux 必跑） |
| 挂载端孤立实体目录（名不在正本，退役残留/未登记资产） | 非链接实体目录且名不在 masters 集 → FAIL；`_`/`.` 前缀豁免（逃生通道） | **有**（selftest case15 + case15b 豁免回归） |
| 路径参数为空字符串（env 设为空串） | 显式空串检查 → 退出码 2（不静默变 cwd 拿假绿） | **有**（selftest case17） |
| 挂载端目录不可读 | iterdir OSError | 无（构造需真实 ACL，selftest 以 monkeypatch 覆盖同类计数，见 case2b/2c） |

判定口径：本清单是**覆盖面声明**，非通过证明。"回归用例覆盖=无"表示该形态有代码判定点但无用例兜底，改动校验器时可能静默失效——与第二节机械承载标注表同一纪律（完整性声明须带覆盖面口径）。回归用例载体：`tools/sync_check_selftest.py`（二十用例，CI 已接线）。

**已知不覆盖（无代码判定点，故不入上表）**：挂载端出现与正本同名的**实体文件**（非目录）时静默放过。深挖轮实测确认（v0.1.5.2）。裁定：不加判定点——各端 loader 按目录发现 skill，实体文件不会被当资产加载，且"文件/目录"边界与链接判定已分列；此处留作显式声明的覆盖边界，非疏漏。

## 四、变更门禁

- 改动正本的 **skill 内容** 后，各端需重开会话做**双向触发测试**：正向触发命中率 >90%，负向抽检误触发 <5%。
- **维护件豁免**：校验脚本、README、裁定记录等不被加载器读取的文件，其改动不触发门禁。
- 门禁针对"被 Agent 实际加载的内容"，这是判定豁免边界的唯一标准。

## 五、台账纪律

- 挂载结构变更（建链/拆链/收编/隔离）当日登记，含回滚命令；被替换的旧副本按**零删除原则**移出原位归档，不物理删除。
- 任何"两端不一致"的结论，先排除三类伪差异：行尾异构、展示层截断、配对键选错。

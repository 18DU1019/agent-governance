# 会话收尾闭环流程（Closure Workflow）

定位：多轮 Agent 会话结束时的**收口纪律**——把"这轮聊了什么"转化为"体系记住了什么、文件去了哪里、还有什么没关"。防止三类慢性病：口头结论丢失、交付文件散落工作区、未完成事项无人认领。

## 四步闭环

### 1. 未完成事项汇总

逐条列出本轮：已闭环项（含验证证据）/ 在飞项（含中断点）/ 需人工决断的争议点（不代裁，显式回抛）。写入记忆文件，**下轮会话启动时优先检查上轮未完成项**——挂账不复核等于没挂。

### 2. 记忆沉淀（蒸馏而非倾倒）

- 会话记忆 → 结构化条目：只保留"下轮不可从磁盘/git 恢复的信息"（决策及理由、失败路径、用户纠正）。
- 分层落位：跨会话偏好 → 用户层；项目规则/事故教训 → 项目层；本轮流水 → 会话层。
- 蒸馏产物必须可审计：给出去重后的净条目，不整段复制对话。

### 3. 交付物入库判定

对本轮产出的每个文件回答三问：

1. **是否复制品**？与既有资产内容重复的，合并接链而非新增副本（副本制必漂移，见 junction-discipline）。
2. **落位何处**？按知识库落位规则归档，禁止散落工作目录；归档动作本身入台账。
3. **接链了吗**？孤立文件=不存在——无入链的归档件后续无人可见。

### 4. 轻复检（三标尺）

对沉淀结果做快速检验：与一手事实一致？与既有知识无矛盾冲突？边界条件（何时不适用）已写明？不通过则回改，不带病入库。

## 输出物

一张闭环报告：本轮净裁定（一段话）+ 三态清单（闭环/在飞/待决断）+ 文件去向表 + 下轮启动检查项。

## 反题警示

收尾流程的最强反题是"仪式化空转"——每次收尾产出报告但挂账项连续多轮无人认领，则流程在制造文书而非闭环。健康度指标不是"收尾执行率"而是**挂账项的半衰期**：多数在飞项应在 2-3 轮内被认领或显式关闭；认领率为零的挂账类别，砍掉该类别的登记义务。

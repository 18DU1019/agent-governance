# Skill 资产生命周期治理条款（Lifecycle Clauses）

定位：主流 Agent 框架（角色编排/任务流转类）普遍覆盖到"资产能用"这一层，本条款集补的是其后两层——**生命周期**（资产何时退役）与**记账一致性**（依据什么数据做退役决策）。适用于任何持续增删 skill/插件/提示词资产的个人或小团队体系。

## 1. 立项纪律：先工作流，后组织位

任何新 skill/新角色的设立，默认序为"先观测到重复出现的任务形态，再立资产承载"。组织先行而工作未至，即占位膨胀，按降档条款处理。

## 2. 降档时钟（Sunset Clock）

- 每个资产立项时挂一个到期时钟（默认 30 天），到期依据**真实调用计数**裁决：续期或降档归档。
- 时钟到期只产出"一键可批的默认处置案"，自动机制本身不动手。
- 归档采用隔离目录移出（零删除原则），可回滚。

## 3. 需求真伪检具（记账口径）

降档决策依赖调用计数，计数失真是最高危风险——它会把真需求误判为占位而误拆。治理口径：

- **计入口径**：仅"真实调用/实际运用"计入；交付、治理动作、提及不计；凭证不足不补数（防洗数）。
- **分级**：真需求（有真实工作流接点且重复出现）/ 中强·待排期 / 弱·被动 / 占位（零调用+挂时钟）/ 不立项 / 关闭。
- **口径先行**：先统一记账口径，再改数据列；变更记录区为唯一记账面，汇总列=只读快照。跳过口径直接改数=洗数。
- 定期用会话记录反推审计计数列，低估与高估同等对待。

## 4. 登记三防

任何治理产出新增登记项（台账条目、裁定、清单行）前：

1. **定义复读**：先复述条目类型的准入定义，防把不同层概念登记成同类。
2. **盘点先行**：先全量盘点既有同类项，防重复立项。
3. **反证自检**：给出"什么证据能证明这条登记错了"，给不出即降级为观察项。

## 5. 合议治理（多视角评审纪律）

对方向级议题做多角色合议时：

- **轮答四段制**：判断（一句话）→ 依据（知识源+信源强度）→ 行动 → 保留意见（该视角看到的风险或反题）。
- **盲写先行**：常态级——各视角初答不得引用/呼应前视角结论，分歧留给收束方集中裁决；高利害级（方向取舍/不可逆拆除/资金编制）——各视角用相互隔离的独立上下文真盲写（每视角一次独立调用），会话内盲写只是行为纪律，效力弱于技术隔离。
- **关键数字同轮复核**：高利害合议收束前，独立复核收束将引用的关键数字——每个数字回一手出处核对"数值+口径+来源"三件套；只拦转录/口径/出处类错误，拦不住源头本身错。
- **收束不是取平均**：冲突点显式裁决或悬置登记（悬置必须附重审触发条件，且触发条件本身要写明未经检验）。
- **检验窗口**：新合议纪律试运行以 3 次真实合议为期，逐次记增益/损耗，据证据决定保留或回退。

## 6. 学习转化纪律

完成任何外部学习（对标、论文、书摘、行业报告）后，24 小时内对照自有体系"打一刀"——产出可执行改动清单或明确裁决。边界三条：

- 有具体可砍点才动刀，禁止为凑动作制造改造项；无落点时如实登记"无可执行增量"。
- 动刀涉及他方正本或在制文件时，仍走既有门禁（提案/校验/入库闸门），本纪律不豁免。
- 本纪律只管"学完到落刀"的时限与产出，不改变已收敛议题的关闭效力。

## 7. 信源纪律（全员）

- 一手信源优先；二手内容标注推测属性，交叉验证后方可作为行动依据。
- 跨指标比较禁止直接相减——验收线必须与评估工具同指标、同任务集、同链路对齐；从严口径走同 harness 的决定性实验。
- 证据强度不对称：截断清单上"读出在列"有效，"读出不在列"无效（可能被截断吃掉）；定谳需运行时探测。

## 8. 反题义务

任何断言呈现其最强版本反题，反题须来自同等强度论据；合题不得是两端取平均。低概率高损失型风险（如版权暴露）单列"风险偏好问题"回抛决策者，不代裁。

## 9. 执行前复扫（Pre-execution Re-check）

- 门禁**批准时点**与**执行时点**之间若存在状态漂移可能（跨会话轮次，或期间有其他写者动过目标面），执行时点必须重跑关键校验，禁止引用批准时点的旧读数作为放行依据。
- 同轮连续"批准即执行"不强制复扫——复扫税只在漂移风险真实存在时收，否则即仪式化空转（与 closure-workflow 反题条款同一条纪律）。
- 典型形态：push 前 SOP 全量重扫（不信任提案轮次的脱敏扫描结果）、降档时钟到期裁决前重跑调用计数。

## 10. 清洗与验证不得共用同一把尺（仪器正交）

脱敏/净化类动作（历史重写、批量替换、发布前洗词）的**清洗模式集**（denylist：枚举已知敏感值）不得直接充当**验收模式集**。两者共用同一份枚举时，枚举未覆盖的形态清洗漏改、验收也漏检，必然产出"自证式零残留"——这是公理 1 口径律在机制层的复发，本仓自身即三实例（v0.1.3 脱敏轮 → v0.1.5.1 勘误 → 案乙历史重写终扫，三次"归零"均由同一残缺模式集自证）。

- **正交化**：验收仪器改按**形态匹配 + 白名单显式放行**（默认可疑，失误方向与 denylist 相反），不复用清洗枚举；工具实例 `tools/desensitize_scan.py`。
- **口径声明**：验收仪器须自带所扫集合口径（覆盖形态类 / 已知不覆盖的残余面 / 扫描对象范围）；其"通过"只声明该口径内零命中，不声明"干净"。
- **残余面兜底**：形态上不可分的残余（如单独出现、无路径上下文的中文私有专名）须显式登记并交人工/模型通读，不得默认"仪器零命中即无残留"。
- **对象层口径**：清洗与验收均须显式声明**作用对象层**——git 对象层（commit/blob/tag，历史重写可达）／工作树文本层（形态仪器可达）／**非 git 对象层**（issues/PR/discussions/Release 正文/wiki，历史重写与工作树仪器**均不可达**，须逐条删除或平台侧清除）。三层混同是"重写即彻底"类虚警的来源。
- **接线**：验收仪器入 CI（自测 + 全仓扫描），使条款由行为纪律升为每轮机械拦截。

### 本仓自身适用缺口（如实登记）

- **生命力判据缺口（本仓最强反题）**：本仓为 skill 资产设计退役时钟（条款 1/2），自身却无调用计数（无 telemetry、无安装统计）——"治理他人退役的仓，自己的退役依据是空的"。合题方向：以"被 fork / 被引用 / 被改造"替代"被调用"作外部可观察的生命力信号，本仓尚未建立此类内部判据。此缺口不修复并显式登记：本仓定位为对外发布作品，退役时钟对其不适用；登记本身即条款 8 的实例。
- **映射面缺口**：本表只覆盖"仓内可自证"的条款执行证据，不覆盖"条款↔原体系事故"映射。
